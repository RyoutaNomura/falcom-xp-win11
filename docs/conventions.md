# スクリプトを触るときの規約

守らないと**動作はするが読めない**、あるいは**動いている環境を壊す**類のものを明文化しておく。

---

## 1. ファイルの文字コードと改行

| ファイル | リポジトリ上 | 生成物 | 理由 |
|---|---|---|---|
| `*.ps1` / `*.psm1` / `*.psd1` | **UTF-8 (BOM あり) / CRLF** | — | **PowerShell 5.1 は BOM 無し UTF-8 を ANSI として読む。** BOM が無いと日本語が化け、文字列比較や `Write-Host` が壊れる |
| `*.ini.tmpl` | UTF-8 / LF | — | GitHub 上で読める形にしておく |
| `ddraw.ini` など生成される ini | — | **CP932 / CRLF** | **cnc-ddraw は ini を ANSI として読む。** UTF-8 で書くとコメントの日本語が化ける |
| `*.cmd` | UTF-8 / CRLF | **CP932 / CRLF** | `cmd.exe` が ANSI として読む |
| `*.md` | UTF-8 / LF | — | — |

**変換はスクリプトの出口だけで行う。** リポジトリ上のテンプレートは UTF-8 のままにし、
`Write-Ansi` が書き出すときに CP932 + CRLF へ落とす。

[`.gitattributes`](../.gitattributes) と [`.editorconfig`](../.editorconfig) で機械的に守らせている。

**ファイル名は ASCII。** 日本語ファイル名は GitHub の URL がパーセントエンコードになって
リンクが読めず、CP932 を経由するツールで壊れる（拡張子ごと消えることがある）。
見出しの日本語タイトルは各ファイルの冒頭に残す。

## 2. セットアップスクリプトの設計原則

### 2.1 ゲーム本体のファイルには一切触れない

追加するのは `ddraw.dll` と ini とバッチだけ。DLL インジェクションもしない。
**やめるときは `ddraw.dll` を消してレジストリを1行消すだけ**で完全に戻る。

### 2.2 動いている設定を黙って上書きしない

セットアップスクリプトが既存の設定を無条件に書き戻すと、
動いていた環境が起動しなくなる（`16BITCOLOR` を消す、`ScreenMode` を戻す、など）。

| 原則 | 実装 |
|---|---|
| 既定は「触らない・表示するだけ」 | `-GameScreenMode keep` が既定 |
| 変更はパラメータで明示的に要求されたときだけ | `-GameScreenMode window` / `fullscreen` |
| 既存値を正としたいときの逃げ道を用意する | `-KeepCompat` / `-KeepExistingProfiles` |
| 何も変更せず現状だけ見るモードを持つ | **`-VerifyOnly`** |

**`-VerifyOnly` を常用モードにする。** 「何かおかしい」と思ったらまずこれを実行して
現状と期待値の差分を見る。セットアップは差分が分かってから流す。

### 2.3 書き換える前に `*.bak` を1つ作る

既に `.bak` があれば上書きしない（初回の状態を失わないため）。`Backup-Once` が担当する。

### 2.4 `-WhatIfOnly` / `-VerifyOnly` で本当に何もしない

ファイル・レジストリ・**ネットワーク**・**クリップボード**の全てを抑制する。
変更操作は必ず `Test-Change` を通すこと。`Test-Change` が `$false` を返したら何もしない。

外部コマンドの起動もここに含まれる。`ludusavi backup --preview` は読み取りに見えるが、
マニフェスト更新のネットワークアクセスと `%APPDATA%\ludusavi` への書き込みを伴うので
`$NoChange` で止める。

### 2.5 config.yaml はブロックを限定して編集する

ludusavi の `config.yaml` には `backup:` と `restore:` に**同名のキー**（`toggledPaths` /
`toggledRegistry` / `ignoredGames`）がある。パターンをファイル全体に当てると
別セクションを巻き込んで壊す。

`Find-TopLevel` → `Find-LineUnder` で親ブロックを特定してから、その配下だけを対象にする。
既存エントリの検出も同様に、全文の部分一致ではなく該当ブロック配下の行だけを見る
（前方一致する別名の誤検出と、引用符付き表記での重複追加を防ぐ）。

### 2.6 各ゲームのフォルダは単体で完結させる

`games/<id>/` を丸ごとコピーすれば動くこと。共通モジュールを `lib/` に置いて依存させると、
ハンドヘルド端末へ1タイトルだけ持ち出せなくなる。

代償として ED3 と ED4 のスクリプトには重複がある。**片方を直したらもう片方も見ること。**
構造は意図的に対称にしてある（章立て・関数名・パラメータ名を揃えてある）ので、差分を取れば分かる。

## 3. 公開前のチェック

- [ ] **ユーザー名を含む絶対パス**（`C:\Users\<name>\...`）→ `%APPDATA%` などに置き換える
- [ ] **ludusavi の `config.yaml` の中身をそのまま貼らない**
      （`cloud.remote` の ID や rclone のパスが個人情報になる）
- [ ] **Playnite の引数例に実際のユーザーパスを残さない**
- [ ] ゲーム本体・`DLLDV\` の DLL・セーブデータが入っていない
- [ ] cnc-ddraw 本体（`ddraw.dll` / `Shaders`）を同梱していない
      （[公式リリース](https://github.com/FunkyFr3sh/cnc-ddraw/releases) から取得する形にしてある）

`.gitignore` でひととおり弾いているが、ドキュメント中の記述は弾けないので目視すること。

```powershell
Select-String -Path .\**\*.md, .\**\*.ps1 -Pattern 'C:\\Users\\'
```

## 4. git を扱うときの注意

**Windows 側から操作すること。** WSL や Linux 側のマウント越しに `git` を実行すると、
ファイルモード（`100644` → `100755`）とファイル名の文字コード変換が差分として出て、
実体は変わっていないのに全ファイルが変更扱いになる。

どうしてもマウント越しに触る必要があるなら:

```
git config core.fileMode false
```
